# BoN Chess — пилот сервиса шахматной школы

Веб-сервис, работает в браузере, есть мобильная вёрстка. Пилот запускается в **тестовом режиме**: данные вымышленные, есть быстрый вход и тестовое подключение Lichess.

## Быстрый старт

Нужен Node.js 20+ (проверено на 22).

```bash
cd chess-school
cp .env.example .env
npm install
npm run setup      # создаёт базу и наполняет её тестовыми данными (~30 с)
npm run dev        # http://localhost:3000
```

Вариант для боевого запуска: `npm run build && npm run start`. Также есть `docker compose up --build`.

Чтобы сбросить базу к исходным тестовым данным: `npm run db:reset`.

### Тестовые входы (пароль у всех `demo123`)

| Логин | Кто |
|---|---|
| `andrey` | Андрей, администратор: журнал, оплаты, переносы, задачи |
| `coach1` … `coach4` | Тренеры (по 25 учеников) |
| `s001`, `s002` | Ученики с богатой историей (игра, карточки, ачивки) |
| `s003` … `s098` | Остальные ученики |
| `s099` | Ученик без подключённого Lichess |
| `s100` | Новый ученик: проходит онбординг (согласие на ПД, затем Lichess) |
| `p001` … `p070` | Родители. У `p061`–`p070` по двое детей, `p002` ещё не дал согласие |

На странице входа есть кнопки быстрого входа.

## Что реализовано

### Журнал Андрея (`/admin`)
- Все ученики. По каждому видны тренер, родитель, **баланс занятий**, количество пройденных занятий, сумма оплат, дата последней оплаты и **кнопка истории переносов**: число всех переносов и число переносов со списанием.
- Оплата вносится вручную: **+N занятий и +N паков карточек** (10 занятий = 10 паков).
- **Баланс уменьшается, когда тренер нажимает «Начать урок».** Уход в минус разрешён.
- **Переносы и отмены.** Если до начала меньше 2 часов, занятие списывается автоматически. Каждый перенос фиксируется: когда, было → стало, сколько часов оставалось, кто перенёс, причина.
- Каждое изменение баланса записывается в журнал движения (оплата, старт урока, поздний перенос, ручная корректировка с обязательной причиной).
- Карточка ученика (`/students/:id`): занятия, переносы, оплаты, движение баланса, студии и оценки, игра и ачивки.
- Расписание по неделям, журнал переносов, оплаты, люди (тренеры и родители), база задач.

### Студии Lichess и домашка
- Тренер открывает урок и **подтягивает свои студии из Lichess** (API `GET /api/study/by/{username}`). Каждую студию он относит к одной из групп: **занятие**, **домашка** или **доделать**. Студию можно добавить и по ссылке.
- Тренер **оценивает домашку по 5-балльной шкале** одним нажатием и может оставить комментарий (`/coach/homework`).
- Ученик видит студии по трём группам. Срока сдачи у домашки нет.

### Вход
- Свой логин и пароль, плюс **обязательное подключение Lichess** для учеников и тренеров (OAuth PKCE, регистрировать приложение на Lichess не нужно).
- При первом входе ученик или родитель **даёт согласие на обработку ПД**. Если ученику меньше 14 лет, указывается ФИО родителя.
- В тестовом режиме Lichess можно подключить, просто указав ник.

### Игра «Тренируй гроссмейстера» (`/game`)
- Выбирается гроссмейстер из **топ-50**. Его **карточка должна быть собрана**; для старта один гроссмейстер с мест 31–50 даётся бесплатно.
- Задачи берутся из собственной базы (не из Lichess). Правило: **одна правильная цепочка ходов**, соперник отвечает сам. **Второй попытки нет**: ошибка сразу засчитывается. Ранее нерешённая задача может выпасть снова.
- У персонажа свой **рейтинг** (Эло против рейтинга задачи) и **игровые уровни** 1–30: Пешка → Конь → … → Гроссмейстер → Легенда.
- Сменить гроссмейстера можно, но **с потерей уровня**: новый персонаж начинает с рейтинга 1000 и уровня 1.
- Задачу подбирается под рейтинг персонажа (±250).
- Администратор добавляет задачи вручную в `/admin/puzzles`: позиция видна на доске, ходы проверяются на легальность.

### Коллекция карточек (`/cards`)
- 200 исторических и современных великих шахматистов, включая всех чемпионов мира.
- Четыре редкости:

| Редкость | Места | Частей на карточку | Шанс выпадения части |
|---|---|---|---|
| Легендарная | 1–20 | 12 | 4% |
| Эпическая | 21–60 | 8 | 13% |
| Редкая | 61–120 | 5 | 28% |
| Обычная | 121–200 | 3 | 55% |

- В паке 5 частей. Чтобы собрать всю коллекцию, нужно около 1100 частей, то есть порядка 250–300 паков. Коллекция «длинная», как и просили.
- **Повторные части** (у уже собранной карточки) превращаются в осколки: обычная даёт 1, редкая 2, эпическая 4, легендарная 8. Осколки **обмениваются на часть любой нужной карточки**: стоимость в 6 раз выше.
- Откуда берутся паки: **10 паков за 10 оплаченных занятий** и **за достижения в решении тактики**.
- Портреты пока тестовые, «игровые»: генерируются в SVG. Чтобы подставить арты, заполните поле `Grandmaster.imageUrl`.

### Ачивки (`/achievements`)
- 28 достижений: тактика (выдают паки), игра, коллекция, занятия, домашка. Список в `src/lib/achievements.ts`.
- Три вида: **календарь** (что и когда получено), **журнал** (хронология), полный список.

### Рейтинг и сравнение
- Общий рейтинг игроков строится **по самому рейтинговому персонажу** (пик). Есть второй вид — по размеру коллекции.
- **Сравнение коллекций** с любым игроком: различия, только у меня, только у него, у обоих.

### Кабинет родителя (`/parent`)
Баланс, ближайшие занятия, домашка и оценки, движение баланса, переносы, персонаж и ачивки ребёнка. Если детей несколько, между ними можно переключаться.

## Бизнес-правила в одном месте
Файл `src/lib/config.ts`: порог переноса (2 ч), число паков за занятие, цена занятия по умолчанию, стартовый рейтинг. Механика карточек в `src/lib/cards.ts`, уровни и рейтинг в `src/lib/game.ts`.

## Технологии
- Next.js 15 (React 19, серверные компоненты и server actions), TypeScript.
- Prisma ORM. Пилот работает на SQLite (один файл, ничего ставить не нужно). Для продакшена меняется `provider = "postgresql"` в `prisma/schema.prisma` и `DATABASE_URL`, модели совместимы.
- Доска chessground (та же, что на lichess.org), проверка ходов через chess.js. Ходы ученика проверяются **на сервере**, решение в браузер не отдаётся.
- Сессии: JWT в httpOnly-cookie, пароли хранятся в bcrypt.

## Настоящий Lichess OAuth
1. В `.env` укажите `APP_URL` — публичный адрес сервиса, например `https://chess.example.ru`. Для локальной проверки подойдёт `http://localhost:3000`.
2. Кнопка «Войти через Lichess» ведёт на lichess.org. Тренеру запрашивается право `study:read`, чтобы видеть приватные студии.
3. Если токена нет или Lichess недоступен, на странице урока показываются тестовые студии с пометкой.
4. Для продакшена: `TEST_MODE="false"`. Это отключает быстрый вход и тестовую привязку Lichess.

## Данные
- `data/grandmasters.json` — 200 шахматистов: имя, страна, годы, чемпионство, пиковый рейтинг (заполнен только там, где известен точно), стиль, факт.
- `data/puzzles.json` — 50 стартовых задач рейтингом от 1000.

## Ограничения пилота
- Оплата вносится вручную, онлайн-эквайринга нет.
- Групповых занятий нет. Переносить урок могут тренер и администратор.
- Тексты согласия на ПД тестовые, их нужно заменить юридически выверенными.
- Docker-файл подготовлен, но в среде разработки не запускался.
